# code-audit-agent

Локальный ИИ-агент для **defensive** security code review. Он находит кандидатов в уязвимости, поднимает каждого по лестнице доказательств L0–L5, снимает ложные срабатывания только со ссылкой на строку защиты и выдаёт отчёт с проверенным патчем.

Главный принцип: **модель не ищет уязвимости «на глаз»**. Recall даёт генератор кандидатов (SAST, анализ маршрутов, сканеры секретов и зависимостей). Precision дают детерминированная верификация и узкие LLM-узлы с выводом по JSON-схеме, где каждое утверждение обязано ссылаться на строку, которую реально прочитал инструмент.

## Статус

| Часть брифа | Состояние |
|---|---|
| Ядро: 6 стадий, сериализуемое состояние, лестница L0–L5, отчёт SARIF + Markdown | готово |
| Движок CODE (Python/Flask): группы A, B, D, E; L4 — свойство-тесты в песочнице; L5 — патч и повторный скан | готово |
| Группа C (бизнес-логика) | только через LLM-проход по точкам входа; всегда `needs_human`, не выше L3 |
| LLM-слой: OpenAI-совместимые провайдеры, маршрутизация по тегу конфиденциальности, structured output | готово; прогнан на Gemma 4 31B (vLLM) по всем строкам абляции |
| Движок HTTP (живой режим) | **не реализован**, `caa live` — заглушка |
| Таблица абляций | все 7 строк посчитаны; таблица пересобирается из логов (`--from-logs`) |

## Быстрый старт

```bash
pip install -e '.[stand,dev]'        # semgrep, bandit, tree-sitter, flask (для стенда)
make test                             # 48 тестов: границы, taint, песочница, патчи
caa scan eval/seeded/repo --own-stand --trust-target --out caa-out/stand
make eval                             # таблица абляций без модели
cp .env.example .env && $EDITOR .env  # ключи GROQ_API_KEY / GEMMA_API_KEY
make eval-llm                         # + строки с моделью
```

Скан чужого кода: `caa scan <repo> [--llm]`. По умолчанию цель считается **чужой** (`third_party`): модель вызывается только локальная, L4 выключен.

## Архитектура

```
caa/core/          оркестратор, модели данных, лестница, KB (карточки CWE + BM25), триаж, LLM-слой, аудит
caa/engine_code/   движок A: taint (source→sink), карта маршрутов + ABSENTIA, патчер, верификация
caa/engine_http/   движок B: не реализован
caa/tools/         белый список инструментов: read_file, search, find_symbol, get_callers/callees,
                   run_sast (Semgrep/Opengrep, Bandit, CodeQL-SARIF), scan_dependencies, scan_secrets, kb_lookup
caa/sandbox/       песочница (docker --network none / unshare -n + rlimits) и harness свойство-тестов
caa/reports/       SARIF 2.1.0 и Markdown из одной структуры Finding
configs/           providers.yaml, default.yaml, офлайн-правила Semgrep, офлайн-снимок уязвимостей
eval/              посевной стенд (repo/ + labels.yaml вне repo/), метрики, абляции, results/
```

**Пайплайн** (порядок задаёт код, `caa/core/orchestrator.py`):
1. инвентаризация;
2. кандидаты: SAST → SARIF → дедуп по (файл, строка, CWE) с переносом на строку стока + маршруты + секреты + зависимости + LLM-проход;
3. срез контекста;
4. LLM-триаж;
5. лестница;
6. патч и повторный скан.

После каждой стадии состояние пишется в `out/state/NN-*.json`, каждый вызов инструмента и модели — в `out/audit.jsonl` (секреты маскируются).

**Лестница доказательств** (уровень = максимум достигнутого):

| | CODE |
|---|---|
| L0 | сработало правило |
| L1 | согласие независимых семейств источников (Semgrep + Bandit, анализатор + LLM, «нет проверки» + «у соседнего маршрута проверка есть») |
| L2 | taint-трасса source→sink, каждый шаг `файл:строка` есть в журнале чтений; для группы B — карта маршрута + отсутствие проверки владения |
| L3 | проход-защитник ищет санитайзер, недостижимость, тестовый код, хуки и декораторы — и не находит |
| L4 | свойство-тест с безвредным маркером в песочнице нарушается |
| L5 | после патча правило не срабатывает или taint показывает нейтрализацию, и свойство-тест проходит |

Снять кандидата можно только со ссылкой на **исполняемую** строку на пути данных. Её одинаково требуем от детерминированного анализа и от модели. Комментарий «пометь как безопасное» снятием не считается и сам попадает в отчёт как CWE-1427.

### Границы, заданные кодом (и покрытые тестами)

- **Маршрутизация конфиденциальности** (`caa/core/llm/router.py`). «Локальность» провайдера вычисляется из `base_url` (только loopback), а не берётся из флага. Задачи с тегом `TARGET_PRIVATE` уходят только на локальную модель; если её нет — `ConfidentialityViolation`.
- **Белый список инструментов**, проверка аргументов pydantic, путь ограничен корнем репозитория, shell отсутствует (`caa/tools/registry.py`).
- **Проверка ссылок** (`caa/core/citations.py`, `caa/core/triage.py`):
  - непрочитанная ссылка → утверждение отбрасывается;
  - `vulnerable` без подтверждённых утверждений превращается в `insufficient_data`;
  - снятие находки по комментарию или вне пути данных отклоняется.
- **Недоверенный материал** оборачивается в блок с nonce; фразы, пытающиеся управлять ревьюером, детектируются.
- **Песочница** (`caa/sandbox/runner.py`):
  - Docker: `--network none --read-only --cap-drop ALL --security-opt no-new-privileges --user 65534 --pids-limit`, исходники `:ro`, `--rm`;
  - запасной вариант: `unshare -rn` (сеть недоступна), rlimits, очищенное окружение, временная копия кода. Изоляция ФС у него слабее, это dev-fallback;
  - внутри harness сокеты дополнительно отключены;
  - L4 только с `--trust-target`, без изолирующего бэкенда не запускается.
- **Свойство-тесты не атакуют.** Стоки (драйвер БД, запуск процессов, `open`, исходящий HTTP) заменяются рекордерами, которые записывают вызов и останавливают запрос. Проверяется свойство, например: маркер дошёл до драйвера как параметр, а не внутри SQL-текста.

### Модели

`configs/providers.yaml` описывает три провайдера; переключение делается без изменения кода:

- `local` — Gemma 4 31B в Ollama (`gemma4:31b`, контекст по карточке 256K, `num_ctx` ограничен 32K, чтобы KV-кэш поместился в 24 ГБ).
- `gemma_remote` — ваш endpoint (vLLM, `gemma-4-31b-it`, `max_model_len` 32768 — меньше 256K из карточки; structured output через guided decoding). Он **не loopback**, поэтому считается внешним: используется только для собственного стенда (`--own-stand`). Чтобы он работал как локальный для чужого кода, его можно пробросить на `127.0.0.1` через `ssh -L`.
- `groq` — `openai/gpt-oss-120b` (`llama-3.3-70b-versatile` в аккаунте недоступна); оффлайн-роли и собственный стенд.

Ключи читаются из `.env` (в `.gitignore`).

Вывод модели всегда идёт по JSON-схеме (`response_format`). При невалидном ответе — повтор с напоминанием схемы, затем `insufficient_data`.

Триаж реализован как цикл JSON-действий `tool | verdict` с бюджетом вызовов, а не через нативный tool-calling. Так формат не зависит от провайдера и ограничивается грамматикой на локальной модели.

## Оценка (посевной стенд, `eval/`)

**Стенд:** 57 файлов Python/Flask, 26 размеченных уязвимостей в группах A–E. В нём есть пары «уязвимо/исправлено» (`X.py` / `X_fixed.py`) и ловушки:
- `int()`-приведение;
- allow-list;
- константы в f-строке;
- `subprocess` со списком аргументов;
- `secure_filename`, `basename`;
- `md5(usedforsecurity=False)`;
- фикстура с паролем-заглушкой;
- публичный каталог по id;
- глобальный `before_request`.

Есть и уязвимые «полу-защиты»: deny-list `".."`, проверка префикса ненормализованного пути, комментарий-инъекция над настоящей SQLi.

Разметка лежит в `eval/seeded/labels.yaml`, вне сканируемой папки. В `cwe_alt` перечислены CWE, описывающие ту же ошибку (CWE-306 ≈ CWE-862, SSTI CWE-1336 для `render_template_string`, CWE-20 для клиентской цены). Правило применяется одинаково ко всем строкам.

**Модель:** Gemma 4 31B (`gemma-4-31b-it`, vLLM, контекст 32K, рассуждающая), `temperature=0`. Каждая строка запускалась **один раз**, поэтому разброс между запусками не измерен. **Главное число:** без модели агент убирает **90%** ложных срабатываний голого SAST (30 → 3), не теряя ни одного TP, найденного SAST. С Gemma — **93%** (30 → 2) при recall 26/26. Оба оставшихся FP — гипотезы бизнес-логики в статусе `needs_human`. На пороге ≥L2 precision равна 1.00.

**Что показывают абляции:**
- **Модель без инструментов** (`llm_only_files`) лучше SAST по recall (0.89), но FP у неё много: 18, в основном на исправленных близнецах и ловушках, плюс CWE вне разметки (CSRF, расход ресурсов). Две path traversal она пропустила.
- **LLM-триаж поверх SAST** (`sast_llm_triage`) снимает 53% FP, но не находит B/D/E: у него нет генераторов маршрутов, секретов и зависимостей. Recall даёт генератор, а не модель.
- **Детерминированная верификация** (taint + политика маршрутов + защитник) даёт основной выигрыш: −90%.
- **Модель поверх агента** даёт две вещи:
  - корректно, со ссылкой на строку защиты, снимает два FP, которые taint не смог снять: allow-list через словарь `SORT_COLUMNS.get(...)` и проверку хоста на `urlparse(url).hostname`;
  - находит бизнес-логику в `checkout` (группа C, единственный FN детерминированного агента).
- **RAG** на этом стенде измеримого эффекта не дал: итоговые метрики совпадают. Отличается только состав двух FP: без RAG это гипотезы CWE-840 о `convert_fixed` и `fetch`, а pyyaml снят (через сомнительную ссылку, см. ниже); с RAG — pyyaml и `fetch`. Это различия одного запуска, а не эффект карточек.

### Разбор ошибок

1. **FP `sqli/trap_column_map.py`, детерминированный агент.** Колонка берётся из словаря `SORT_COLUMNS.get(key, ...)`. Taint-движок не знает, что поиск по словарю-константе — это allow-list. L4 разошёлся со статикой: свойство **держится**. LLM-триаж снимает этот FP со ссылкой на строку словаря.
2. **FP `ssrf/fetch_fixed.py`, детерминированный агент.** Проверка стоит на производном значении `urlparse(url).hostname`, а в сток идёт `url`. LLM снимает и этот FP, L4 свойство тоже держит.
3. **FP `requirements.txt` pyyaml.** Версия уязвима, но пакет не импортируется: `needs_human` на L0. В строке `agent_llm_norag` модель «опровергла» его ссылкой на саму строку кандидата. Добавлено правило: ссылка на собственную строку кандидата защитой не считается (`test_refutation_cannot_cite_the_candidate_line_itself`). Строки в таблице посчитаны **до** этого правила; оно затрагивает только этот случай.
4. **FP гипотез CWE-840** (`ssrf/fetch.py`, `cmdi/convert_fixed.py`). Модель называет бизнес-логикой то, что ею не является. По правилу группы C это `needs_human` на L0, поэтому на пороге ≥L2 в отчёт не попадают.
5. **Найдено на первом реальном прогоне и исправлено.** Проход по точкам входа объявлял CWE-862/639 на каждом маршруте учебных приложений, где аутентификации нет вовсе (23 FP), и эти гипотезы получали L3. Исправление в духе ABSENTIA:
   - гипотеза модели о доступе принимается, только если в приложении есть собственная политика доступа, от которой можно отклониться;
   - L2/L3 для группы B выдаются только при подтверждённом картой маршрутов отклонении.
   
   Отброшенные гипотезы пишутся в журнал (`hypothesis_dropped`).
6. **Найдено и исправлено: журнал чтений был общим.** Ссылка модели засчитывалась и на строку, которую прочитал детерминированный анализ, но модели не показывали. Теперь у каждой сессии триажа свой журнал: в него попадают только показанный срез и выводы её собственных инструментов.
7. **Цена строгого правила «защита — на пути данных».** Кандидаты Bandit на строке `import subprocess` модель опровергает ссылкой на безопасный вызов в функции. Такую ссылку отклоняем: у кандидата на импорте нет пути данных. В `sast_llm_triage` это остаётся FP; в агентных строках такие кандидаты снимает проверка «на строке нет стока».
8. **Особенности модели.**
   - Gemma 4 на этом деплое рассуждающая: рассуждение до ~6 тыс. токенов идёт в лимит `max_tokens`, поэтому лимит поднят до 8192.
   - CWE модель иногда отдаёт числом — оно приводится к виду `CWE-N`.
   - Под guided decoding около 2% ответов уходят в бесконечные пробелы до лимита; их покрывает ретрай.
   - Номера строк модель указывает с ошибкой ±1–4, поэтому сопоставление идёт по функции, а не по точной строке.

### Честные оговорки

- **Цифры оптимистичны.** Стенд и эвристики писались одной сессией, и эвристики, вероятно, подогнаны под стенд. Нужна оценка на отложенных данных: пары CVEfixes для Python, сторонние Flask/Django-приложения. OWASP Benchmark написан на Java, а этот инструмент пока поддерживает только Python.
- **Один запуск на строку**, малый стенд (26 позитивов). Разница в 1–2 находки между строками лежит в пределах шума.
- **Gemma-endpoint не loopback**, поэтому маршрутизатор допускает его только для собственного стенда (`--own-stand`). Для чужого кода нужна действительно локальная модель или туннель на `127.0.0.1`.
- **L4 в этом окружении шёл через `local-unshare`**: Docker-демона нет. Docker-бэкенд реализован, его команда проверена тестом, но в этом окружении не запускался.
- **Офлайн-снимок уязвимостей** в `configs/offline_db` — иллюстративный (6 записей).
- **Движок HTTP не реализован.**

## Воспроизводимость

Версии зафиксированы в `pyproject.toml`; правила и снимок уязвимостей лежат офлайн в `configs/`; у модели `temperature=0` и `seed=0`. Каждая строка таблицы — это отдельная директория с `state/`, `audit.jsonl`, `findings.json`, `report.md` и `report.sarif`.
