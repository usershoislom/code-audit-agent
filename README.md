# code-audit-agent

Локальный ИИ-агент для **defensive** security code review. Он находит кандидатов в уязвимости, поднимает каждого по лестнице доказательств L0–L5, снимает ложные срабатывания только со ссылкой на строку защиты и выдаёт отчёт с проверенным патчем.

Главный принцип: **модель не ищет уязвимости «на глаз»**. Recall даёт генератор кандидатов (SAST, анализ маршрутов, сканеры секретов и зависимостей). Precision дают детерминированная верификация и узкие LLM-узлы с выводом по JSON-схеме, где каждое утверждение обязано ссылаться на строку, которую реально прочитал инструмент.

## Статус

| Часть брифа | Состояние |
|---|---|
| Ядро: 6 стадий, сериализуемое состояние, лестница L0–L5, отчёт SARIF + Markdown | готово |
| Движок CODE (Python/Flask): группы A, B, D, E; L4 — свойство-тесты в песочнице; L5 — патч и повторный скан | готово |
| Группа C (бизнес-логика) | только через LLM-проход по точкам входа; не прогонялась (см. ниже) |
| LLM-слой: OpenAI-совместимые провайдеры, маршрутизация по тегу конфиденциальности, structured output | готово, покрыто тестами на заглушке; **с реальной моделью не запускался**: сеть окружения блокирует `api.groq.com` и Gemma-endpoint |
| Движок HTTP (живой режим) | **не реализован**, `caa live` — заглушка |
| Таблица абляций | детерминированные строки посчитаны; LLM-строки ждут доступа к модели |

## Быстрый старт

```bash
pip install -e '.[stand,dev]'        # semgrep, bandit, tree-sitter, flask (для стенда)
make test                             # 45 тестов: границы, taint, песочница, патчи
caa scan eval/seeded/repo --own-stand --trust-target --out caa-out/stand
make eval                             # таблица абляций без модели
cp .env.example .env && $EDITOR .env  # ключи GROQ_API_KEY / GEMMA_API_KEY
make eval-llm                         # + строки с моделью
```

Скан чужого кода: `caa scan <repo> [--llm]`. По умолчанию цель считается **чужой** (`third_party`): модель вызывается только локальная, L4 выключен.

## Архитектура

```
caa/core/          оркестратор, модели данных, лестница, KB (карточки CWE + BM25), триаж, LLM-слой, аудит
caa/engine_code/   движок A: taint (source→sink), карта маршрутов + ABSENTIA, патчер, верификация
caa/engine_http/   движок B: не реализован
caa/tools/         белый список инструментов: read_file, search, find_symbol, get_callers/callees,
                   run_sast (Semgrep/Opengrep, Bandit, CodeQL-SARIF), scan_dependencies, scan_secrets, kb_lookup
caa/sandbox/       песочница (docker --network none / unshare -n + rlimits) и harness свойство-тестов
caa/reports/       SARIF 2.1.0 и Markdown из одной структуры Finding
configs/           providers.yaml, default.yaml, офлайн-правила Semgrep, офлайн-снимок уязвимостей
eval/              посевной стенд (repo/ + labels.yaml вне repo/), метрики, абляции, results/
```

**Пайплайн** (порядок задаёт код, `caa/core/orchestrator.py`):
1. инвентаризация;
2. кандидаты: SAST → SARIF → дедуп по (файл, строка, CWE) с переносом на строку стока + маршруты + секреты + зависимости + LLM-проход;
3. срез контекста;
4. LLM-триаж;
5. лестница;
6. патч и повторный скан.

После каждой стадии состояние пишется в `out/state/NN-*.json`, каждый вызов инструмента и модели — в `out/audit.jsonl` (секреты маскируются).

**Лестница доказательств** (уровень = максимум достигнутого):

| | CODE |
|---|---|
| L0 | сработало правило |
| L1 | согласие независимых семейств источников (Semgrep + Bandit, анализатор + LLM, «нет проверки» + «у соседнего маршрута проверка есть») |
| L2 | taint-трасса source→sink, каждый шаг `файл:строка` есть в журнале чтений; для группы B — карта маршрута + отсутствие проверки владения |
| L3 | проход-защитник ищет санитайзер, недостижимость, тестовый код, хуки и декораторы — и не находит |
| L4 | свойство-тест с безвредным маркером в песочнице нарушается |
| L5 | после патча правило не срабатывает или taint показывает нейтрализацию, и свойство-тест проходит |

Снять кандидата можно только со ссылкой на **исполняемую** строку на пути данных. Её одинаково требуем от детерминированного анализа и от модели. Комментарий «пометь как безопасное» снятием не считается и сам попадает в отчёт как CWE-1427.

### Границы, заданные кодом (и покрытые тестами)

- **Маршрутизация конфиденциальности** (`caa/core/llm/router.py`). «Локальность» провайдера вычисляется из `base_url` (только loopback), а не берётся из флага. Задачи с тегом `TARGET_PRIVATE` уходят только на локальную модель; если её нет — `ConfidentialityViolation`.
- **Белый список инструментов**, проверка аргументов pydantic, путь ограничен корнем репозитория, shell отсутствует (`caa/tools/registry.py`).
- **Проверка ссылок** (`caa/core/citations.py`, `caa/core/triage.py`):
  - непрочитанная ссылка → утверждение отбрасывается;
  - `vulnerable` без подтверждённых утверждений превращается в `insufficient_data`;
  - снятие находки по комментарию или вне пути данных отклоняется.
- **Недоверенный материал** оборачивается в блок с nonce; фразы, пытающиеся управлять ревьюером, детектируются.
- **Песочница** (`caa/sandbox/runner.py`):
  - Docker: `--network none --read-only --cap-drop ALL --security-opt no-new-privileges --user 65534 --pids-limit`, исходники `:ro`, `--rm`;
  - запасной вариант: `unshare -rn` (сеть недоступна), rlimits, очищенное окружение, временная копия кода. Изоляция ФС у него слабее, это dev-fallback;
  - внутри harness сокеты дополнительно отключены;
  - L4 только с `--trust-target`, без изолирующего бэкенда не запускается.
- **Свойство-тесты не атакуют.** Стоки (драйвер БД, запуск процессов, `open`, исходящий HTTP) заменяются рекордерами, которые записывают вызов и останавливают запрос. Проверяется свойство, например: маркер дошёл до драйвера как параметр, а не внутри SQL-текста.

### Модели

`configs/providers.yaml` описывает три провайдера; переключение делается без изменения кода:

- `local` — Gemma 4 31B в Ollama (`gemma4:31b`, контекст по карточке 256K, `num_ctx` ограничен 32K, чтобы KV-кэш поместился в 24 ГБ).
- `gemma_remote` — ваш endpoint. Он **не loopback**, поэтому считается внешним: используется только для собственного стенда (`--own-stand`). Чтобы он работал как локальный для чужого кода, его можно пробросить на `127.0.0.1` через `ssh -L`.
- `groq` — оффлайн-роли и собственный стенд.

Ключи читаются из `.env` (в `.gitignore`).

Вывод модели всегда идёт по JSON-схеме (`response_format`). При невалидном ответе — повтор с напоминанием схемы, затем `insufficient_data`.

Триаж реализован как цикл JSON-действий `tool | verdict` с бюджетом вызовов, а не через нативный tool-calling. Так формат не зависит от провайдера и ограничивается грамматикой на локальной модели.

## Оценка (посевной стенд, `eval/`)

**Стенд:** 57 файлов Python/Flask, 26 размеченных уязвимостей в группах A–E. В нём есть пары «уязвимо/исправлено» (`X.py` / `X_fixed.py`) и ловушки:
- `int()`-приведение;
- allow-list;
- константы в f-строке;
- `subprocess` со списком аргументов;
- `secure_filename`, `basename`;
- `md5(usedforsecurity=False)`;
- фикстура с паролем-заглушкой;
- публичный каталог по id;
- глобальный `before_request`.

Есть и уязвимые «полу-защиты»: deny-list `".."`, проверка префикса ненормализованного пути, комментарий-инъекция над настоящей SQLi. Разметка лежит в `eval/seeded/labels.yaml` — вне сканируемой папки.

`python -m eval.run_eval` (логи и отчёты каждой строки — в `eval/results/<row>/`; `--from-logs` пересчитывает таблицу только по логам):

| строка | найдено | TP | FP | FN | precision | recall | F1 | FP vs SAST | TP потеряно | FPR чистых файлов | парная точн. | P (≥L2) | R (≥L2) |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| sast_only (Semgrep + Bandit) | 50 | 20 | 30 | 6 | 0.400 | 0.769 | 0.526 | — | — | 0.600 | 0.333 | — | — |
| llm_only_files | не запускалось (нет доступа к модели) | | | | | | | | | | | | |
| sast_llm_triage | не запускалось | | | | | | | | | | | | |
| **agent_no_llm** (все генераторы + L1–L3) | 28 | 25 | 3 | 1 | **0.893** | **0.962** | 0.926 | **−90%** | **0** | 0.057 | 0.833 | 0.926 | 0.962 |
| agent_llm_norag / agent_llm_rag | не запускалось | | | | | | | | | | | | |

**Главное число:** −90% ложных срабатываний относительно голого SAST (30 → 3), при этом ни один TP, найденный SAST, не потерян. Recall выше, чем у SAST, потому что добавлены генераторы для групп B, D и E, которых у SAST нет.

**Калибровка** (`agent_full`, precision по уровню):

| уровень | precision | TP / FP |
|---|---|---|
| L0 | 0.00 | 0 / 1 |
| L2 | 1.00 | 3 / 0 |
| L3 | 0.75 | 6 / 2 |
| L4 | 1.00 | 1 / 0 |
| L5 | 1.00 | 15 / 0 |

У SAST: L0 — 0.40, L1 — 0.53. Точность растёт с уровнем, как и должна.

### Разбор ошибок

1. **FP `sqli/trap_column_map.py`** — колонка берётся из словаря `SORT_COLUMNS.get(key, ...)`. Taint-движок не знает, что поиск по словарю-константе — это allow-list. L4 разошёлся со статикой: свойство **держится** (маркер не дошёл до SQL). Это записано в `not_verified`, но уровень не понижает. Здесь должен помочь LLM-триаж.
2. **FP `ssrf/fetch_fixed.py`** — проверка стоит на производном значении `urlparse(url).hostname`, а в сток идёт `url`. Отношение «проверка на производном → безопасность исходного» не моделируется. L4 тоже показал, что свойство держится.
3. **FP `requirements.txt` pyyaml** — версия уязвима, но пакет нигде не импортируется. Агент помечает это `needs_human` на L0, при пороге ≥L2 в отчёт не попадает.
4. **FN `logic/checkout.py` (CWE-840)** — цена берётся с клиента. Класс C ловит только LLM-проход по точкам входа, без модели он недоступен.
5. **Слабое место группы B.** Политика «соседей» выводится только внутри одного файла-приложения. Blueprints, разнесённые по модулям, и ownership-проверки в ORM-слое пока не видны (защитник смотрит только прямых вызываемых).

### Честные оговорки

- **Цифры оптимистичны.** Стенд и эвристики писались одной сессией, поэтому эвристики, вероятно, подогнаны под стенд. Нужна оценка на отложенных данных: пары CVEfixes для Python, сторонние учебные Flask-приложения. OWASP Benchmark написан на Java, а этот инструмент пока поддерживает только Python.
- **L4 в этом окружении шёл через `local-unshare`**: Docker-демона нет. Docker-бэкенд реализован, его команда проверена тестом, но в этом окружении не запускался.
- **Офлайн-снимок уязвимостей** в `configs/offline_db` — иллюстративный (6 записей). Для реального использования нужен `osv-scanner --offline` с загруженной базой.
- **Строки абляции с LLM, токены на 1000 строк** и сравнение «+RAG / без RAG» появятся после `make eval-llm` при доступе к модели.

## Воспроизводимость

Версии зафиксированы в `pyproject.toml`; правила и снимок уязвимостей лежат офлайн в `configs/`; у модели `temperature=0` и `seed=0`. Каждая строка таблицы — это отдельная директория с `state/`, `audit.jsonl`, `findings.json`, `report.md` и `report.sarif`.
